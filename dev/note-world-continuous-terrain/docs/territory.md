# 笔记领地：元信息地形与缓存

## 在插件中使用

角色面板底部的「笔记领地 ↗」是辅助入口，点击后才加载独立地图窗口。沿用面板的文字、分隔线和主题颜色。在思源内直接使用当前会话，无需另填请求 Key，也无需启动下面的开发服务。

## 独立开发预览

先在项目目录执行 `npm ci` 安装开发依赖，再运行 `npm run preview:terrain`，打开 http://127.0.0.1:4177/?v=4 。点击「连接思源」输入请求 Key，本机思源需运行在 127.0.0.1:6806。

固定版本 Three.js 0.160.1 在 `third_party/three/` 内，无运行时外部资源请求。需要本地服务，不能直接双击 index.html。

## 生成原则

地形由笔记元信息驱动，使用多尺度平滑场生成自然轮廓。

没有独立的噪声大陆、预制山脉或美术随机假山。相机、光照、色彩与曲面映射系数是展示约定，不承载笔记事实。

## 数据如何成为地形

1. 按笔记本统计 Page 数量，决定区域的相对尺度。
2. 初始区域排布由笔记规模、确定性初始排布、区域间排斥与真实跨本双链吸引共同确定。双链强的区域在初始布局中更容易靠近；这不是严格的语义距离。
3. 在每个笔记本内按 Page ID 前六位的创建年月聚合。没有可解析创建时间的示例 ID 归入 undated 群落，不伪造日期。
4. 群落沿创建顺序分布，字符量差异影响横向偏移。群落大小由 Page 数量占比决定，群落高度源由 Page 数量和累计字符量决定。
5. 群落沿引用关系的主方向延展为椭圆山脊，延展程度由群落 Page 数决定。群落使用有限支撑范围的平滑衰减曲面相融，形成山体、脊线、鞍部、低地和海岸。它是数据场的平滑生成，随后执行确定性的下坡汇水切削：按高度从高到低传播到最陡下降邻点，汇水越多、坡度越大，切削越明显，上限为 4 个高度单位。这是简化的地形塑形，不是完整水力侵蚀或真实地质模拟。
6. 单篇 Page 使用确定性的非网格螺旋落点，按创建顺序分配；字符量决定局部足迹大小及细节高度。
7. 近期更新产生绿意与地标颜色。高处的浅色覆盖同时依赖地形高度与更新时间沉寂度，低处不会仅因陈旧而整片泛白。
8. 每个 30 天内更新的 Page 对应一棵树；没有随机植被。
9. 所选 Page 的双链按地形寻路形成金色道路，跨水以虚线表示。蓝色带箭头引用流汇总最多 12 对跨笔记本有向引用，宽度由引用次数决定；它不是自然河流。
10. 远景隐藏单篇光点，避免大量标记覆盖山体；放大后显露光点与实例化地标。

空库只有海面，删除全部 Page 也会删除宽尺度山体。修改内容会改变所在群落与局部地形。更新时间改变着色，不改变内容与创建聚合形成的高度。

## 高度与解释

局部 Page 权重为 `w=(1-d²/r²)²`，只在足迹半径内贡献。局部密度 D 是 w 之和；局部内容贡献 C 是 `log2(1+chars/1000)/4 × w` 之和。

每个创建月份群落的质量 `m=2+2.2×ln(1+Page数)+1.4×ln(1+字符总数/10000)`，按群落半径计算平滑核；在引用方向坐标系内，椭圆距离平方与支撑半径平方之比为 q 时，`k=exp(-4q)×(1-q)²`（q<1，否则为零）。群落场 M 是 m×k 之和。

生成前高度 `H=-3+20×ln(1+M/12)+1.6×ln(1+C)+0.8×ln(1+D)`。−3 是无笔记时的海底基准，海面约为 0。高度是视觉单位，不是重要性评分。

点击地表或选择笔记可查看参与的月份群落与局部 Page 数、群落质量场、局部内容贡献、理论高度及活跃/沉寂程度。面板同时显示汇水切削后的地表高度与生成前理论高度。实际地形是 192×192 网格插值，存在采样误差。

## 增量与布局记忆

坐标使用存储键 `note-territory-layout-v4`，快照保存布局与采样数据。

普通写作、删除、同笔记本新增不会移动已有地标；新 Page 分配到所属创建月份群落的下一螺旋位置。新月份建立新群落。创建月份分布与尺度作为布局快照保留，不因每次更新全局重排。新增后可能增加局部拥挤，这是后续扩容/局部布局需要处理的边界。

新增有 Page 的笔记本或 Page 跨笔记本迁移，会按完整元信息重建初始布局，界面报告重建。历史坐标快照会影响结果，因此复现需要相同元信息、参考时间和布局快照。

修改内容/删除会使对应 Page 与创建月份群落的旧/新支撑范围失效。每帧预算计算，上传受影响地形块并过渡。群落场用空间索引查询。高度源局部重算完成后，派生汇水切削在整个约 3.7 万点的网格上重新求解，再上传实际变化的块；因此没有宣称所有派生处理都严格局部。静止时停止重绘。

双链变化会更新道路和引用流；已持久化区域不会在每次双链变化时整体移动。引用吸引作用于首次或明确重建布局。

## 本地只读与凭据

仅读取打开的笔记本。服务只监听 127.0.0.1，只接受此预览页面的同源 POST，无任意 SQL、任意文件读取或写笔记接口。

独立预览的 Key 只驻留服务内存；输入成功即清空，不写入文件、日志或浏览器存储。停止服务后清除。插件内不需要 Key。

## 缓存与缓慢整理

使用本机 IndexedDB 保存带版本的中间格式：Page ID、标题、笔记本、更新时间、字符统计、双链、布局和地形采样数组。没有笔记正文或请求凭据；缓存不随思源同步。插件缓存按工作空间区分，独立预览使用自己的本地缓存。清除浏览器站点数据会丢失地图缓存。

打开时先恢复完整缓存，跳过整库读取与地形场生成，仍需重建用于显示的图形。距离上次成功整理不足 24 小时不读取元信息；到期后仅在地图打开且可见时慢慢整理，没有自动更新开关或手动刷新按钮。关闭地图后不安排后续读取。

每次最多一个请求，相邻批次间隔约 3 秒：目录 128 篇、字符统计 64 篇、双链 128 对。每批完成保存断点，关闭后下次继续。未变化 Page 复用已有字符统计。失败延后重试，缓存写入失败则停止整理。初次八千篇规模仍可能需要十余分钟，但可以分多次打开完成。

完整收集成功后才应用删除与替换完整缓存；读取期间保留上一版地图。分批读取并非数据库事务快照，整理过程中发生的编辑可能留到下一轮反映。

## 验证

`node --import tsx --test tests/territory/*.test.ts`（或 `npm test` 执行全仓测试）

模型、服务与缓存测试，覆盖无笔记无山、确定性、无矩形行列、独立多尺度场计算对照、内容/时间因果关系、删除消除全部地形、增量坐标稳定、双链影响初始位置、引用流、寻路、只读服务边界、缓存命中零读取、小批上限及断点恢复。

地形计算在主线程分批执行。首次完整整理和图形重建仍随笔记规模增加而变慢，当前没有 Worker。

## 开发入口

世界计算、整理用例、适配器和展示层位于 `src/features/territory/`。独立服务位于 `tools/terrain-server.ts`，与插件构建使用相同的 TypeScript 浏览器入口；修改源码后需重启独立服务。

完整浏览器验证：先运行 `npm run build` 和 `npm run build:test`，再运行 `npm run verify:territory`。需要 Chrome 和 Playwright，可用 `GAMIFY_RENDER_NODE_MODULES` 指定已安装依赖。验证服务默认使用本机 4188 端口，结束自动关闭，仅使用虚构数据与隔离缓存。
